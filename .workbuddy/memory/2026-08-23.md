## Bug 修复：长文件名路径进入后左面板显示异常 + 布局 1 格溢出（12:27）
- 现象：左面板进入 `C:\Users\chenwei\.auto-coder\.autocodertools` 等长路径/长目录名后，左面板显示异常（错位、推开分隔符与右面板）。
- 根因（两处叠加）：① 类名/长目录名超过列宽时未截断，`padRightDW` 在 name>列宽时原样返回，整行撑宽、把 `│` 分隔符与右面板推斜——已在 `formatEntry` 改为 `padRightDW(truncateDW(name, nameFieldW), nameFieldW)`（先截断再补齐）。② **更隐蔽的根因**：`│`（U+2502 制表符）是"模糊宽度"字符，在本机 CJK 语言环境下 `runewidth.RuneWidth('│')==2`（全角计 2 格），而 `View()` 的分栏数学一直按 1 格扣（`half=(w-1)/2`、`right=w-half-1`），导致 `左49 + 分隔符2 + 右50 = 101 > 100` 终端宽度 1 格溢出，整行换行/位移——这正是 tab 行 101>100 的真实来源（实测 `RuneWidth=2`）。
- 修复：① `View()` 动态测量分隔符真实显示宽度 `sepW := runewidth.RuneWidth('│')`（兜底≥1），改为 `half=(w-sepW)/2`、`right=w-half-sepW`，使 `左 + sepW + 右 == w` 恒成立（1 格分隔符环境下自动退化为 49/1/50）。② `renderPane` 把 tab 行与 path 行 `padRightDW(..., w)` 补齐到面板宽度：固定分隔符列位置（避免短路径行让分隔符漂移），并让激活面板的反色路径条铺满整列。

## 启动卡加载中第二次修复 v0.4.1
- 用户报告：v0.4.0 后仍卡在"加载中"，status bar 不在底部。

  1. tea.Tick 只发一次消息，必须 Update 显式 reschedule 才能延续，v0.4.0 漏了这一步。

  3. asyncReload goroutine 写 t._reloadCh（cap=1 buffer），如果 fs.ListDir 在 tick 之后完成，channel 数据无人消费，tab 永远卡加载中。

- 修复：
  - tickReloadCmd() 返回 tea.Tick cmd，每次 reloadTickMsg reschedule 下一次。
  - 抽 drainReloadResults()，在 Update 所有路径后都调一遍。
  - nil guard 让 drain 容忍 partial model。
  - renderList visible = h-1。list 区域只需让 1 行给底部。
  - renderPane 强制 pane 高度 = m.height - 1，padRowsToHeight 补齐空白行。

## Bug 修复：非最大化窗口标签栏消失（22:16–22:40）
- 现象（用户）："在全屏下有标签栏。一旦切换到非全屏，标签栏就不见了。"
- 第一性原理追踪：
  1. `View()` 输出总行数 = `paneHeight + 1`（renderPane 用 `padRowsToHeight` 把面板块补到 `m.height-1` 行）+ bottom 状态栏 1 行 = **恰好 `m.height` 行**。
  2. 正如 `clampRowWidth` 注释所述，ConPTY / Windows Terminal 在非最大化时报告的高度比真实可绘制行数大 1~2 行（shell 把含边框的外尺寸当内容区上报）。
  3. 我们输出 `m.height` 行，但终端实际只能画 `m.height-1~2` 行。多出的行触发终端滚动，最顶行（row 0 = 标签栏）被推出可视区域 → 标签栏消失。最大化时 ConPTY 报告准确，`m.height` 行刚好填满，故正常。
  4. 此前 `renderList` 用 `h-5` 多减 slack，整体输出偏少不会溢出；v0.4.1 改成 `paneHeight=m.height-1` + `visible=h-1` 后输出恰好等于 `m.height`，一旦 `m.height` 偏大 1~2 行即溢出、把 row 0 顶出屏幕。
- 修复（view.go / mouse.go / layout_test.go）：
  - `View()` 引入 `paneH := h - 2`（pane 区），再加 bottom 1 行 = **`h-1` 行输出**，预留 1 行 slack 吸收 ConPTY 高度偏差；`renderPane(p, active, half, paneH)` 透传 paneH。
  - `renderPane` 签名加 `paneH int`，内部 `paneHeight := paneH`，`padRowsToHeight(joined, paneH, w)` 保证面板块 = paneH 行。
  - `renderList` 的 `visible := h - 2`（tab+path 占 2 行，slack 改由 View 层统一预留）。
  - `mouse.go` 的 `mouseListRow` / `ensureCursorVisible` 的 `m.height - 5` → `m.height - 3`（列表区 = 总高-1 减 tab/path 2 行），与渲染布局对齐，防点击错位。
  - `TestViewNeverExceedsHeight` 强化为 `lines <= h-1`（原 `lines <= h` 漏检此回归）；新增 `TestTabBarOnRowZero` 锁定 row 0 含左右 tab 标签文本。
