# 2026-08-24

## Bug 修复：含破折号"——"文件名显示错位（09:26–09:35）
- 现象（用户）：处理文件名含"——"（em dash U+2014）时造成显示错误。
- 第一性原理追踪：
  1. 宽度算法不统一：bubbletea/lipgloss 实际渲染用 `lipgloss.Width`，而 `truncateDW`/`padRightDW`/`padLeftDW` 之前用 `runewidth.RuneWidth`/`runewidth.StringWidth`。
  2. 两把尺子对**模糊宽度字符**判定冲突：本机实测 `runewidth.RuneWidth('—')=2` 但 `lipgloss.Width('—')=1`；`runewidth.RuneWidth('│')=2` 但 `lipgloss.Width("│")=1`。
  3. 后果：`truncateDW` 按 runewidth 把"——"当 4 格预算，但终端 lipgloss 实际只画 2 格 → 含 em dash 的文件名行在 lipgloss 视角比预算窄 2 格 → size 列向左偏移 2 格、与同行其他列不对齐（显示错误）。
  4. 更隐蔽：分隔符"│"在 lipgloss 下占 1 格，但 `View()` 的 `sepW` 用 `runewidth.RuneWidth('│')=2` 扣宽度，导致右面板少算 1 格（与 ConPTY 宽度偏差叠加偶发溢出）。
- 修复（统一为 lipgloss.Width 单一权威尺子）：
  - `truncateDW`：单字符宽度预算从 `runewidth.RuneWidth(r)` 改为 `lipgloss.Width(s[i:i+size])`（与终端实际绘制一致）。
  - `padRightDW`/`padLeftDW`：`runewidth.StringWidth` → `lipgloss.Width`。
  - `View()` 的 `sepW`：`runewidth.RuneWidth('│')` → `lipgloss.Width("│")`（=1，与真实渲染一致）。
  - `mouse.go` 的 `sepCol()` 硬编码 `sepW:=2` → `lipgloss.Width("│")`；`runeWidthOf`/`contextMenuWidth` 的 `runewidth.StringWidth` → `lipgloss.Width`。
  - 测试：`layout_test.go`/`layout_tab_test.go` 内宽度断言从 `runewidth.StringWidth`/`runewidth.RuneWidth` 全面改为 `lipgloss.Width`，`sepW` 同步；删除 runewidth import（view.go/mouse.go/layout_test.go/layout_tab_test.go）。
  - 新增 `TestAmbiguousWidthAlignsColumns`（含 em dash 的 formatEntry 行 lipgloss 宽度必须 == 纯 ASCII 行，锁死列对齐）+ `TestTruncateDWUsesLipglossWidth`（truncateDW 对"——"按 lipgloss 2 格预算）。
- 验证：go vet 干净；go test ./... 全绿；临时诊断确认所有含"│"行 lipgloss 宽度恒等于终端宽（无溢出/无短缺）。
- 构建：dist/tcmd64.exe(5.31MB) / dist/tcmd386.exe(5.00MB) 双架构重建。
- Release: v0.4.3。
- 经验沉淀：TUI 列对齐类 bug 一律以 `lipgloss.Width` 为唯一宽度尺子（它=终端真实绘制），禁止混用 runewidth；模糊宽度字符（em dash '—'、弯引号、│、全角破折号等）是主要雷区。
